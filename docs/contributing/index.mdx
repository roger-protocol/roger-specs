Thank you for helping build the Roger Protocol! This section contains everything you need to know to contribute effectively.

## Before You Start

Make sure you're familiar with:
- [Conventional Commits](https://www.conventionalcommits.org/) (how commits must be written)
- [Semantic Versioning](https://semver.org/) (how we version releases)
- [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) (the key words MUST, SHOULD, etc.)

## Core Principles

### Federated First
Every feature should be designed with federation in mind. Changes should not assume a single-node setup.

### Backward Compatibility
All features must maintain backward compatibility in patch/minor versions. Breaking changes only happen in major versions.

### Type Safety
All route definitions use Zod schemas for type safety. The OpenAPI spec is auto-generated from these schemas.

### Module Boundaries
Keep the codebase modular:
- Core features **cannot** import from optional features
- Optional features are decoupled and cannot import from other features
