## Overview
The `/features` endpoint exposes the node's supported features and their configuration as a JSON dictionary with the feature identifier as the key and the configuration as the value.

## When to use it
- **Right after calling /version:** After calling `/version`, call `/features` to get the configuration of the node, things like the maximum username lenght a user can have, rate limits etc...

## Client best practices
- **Cache the response:** Like the `/version` route, a node's config rarely changes so you should cache the response of `/features` so your client can access the node's config quickly.
- **Set a timeout on the config:** Refetch the config after a certain period of time to stay up to date with the node.
